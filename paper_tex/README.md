# ProteinIK — IEEE two-column LaTeX manuscript

LaTeX conversion of [`../paper/academic.md`](../paper/academic.md). Same text, same
numbers, same reference list; retypeset as an IEEE conference manuscript.

```
paper_tex/
├── main.tex          the whole paper — self-contained, no .bib needed
├── figures/          vector PDFs from paper/figures/*.py
├── tables/           optional generated tables (not used by default — see below)
└── README.md
```

## Compiling

Drop this folder into Overleaf (or any LaTeX viewer) and compile `main.tex`
with **pdfLaTeX**. Two passes resolve the cross-references:

```bash
latexmk -pdf main.tex        # preferred
# or
pdflatex main.tex && pdflatex main.tex
```

No BibTeX run is needed — the bibliography is a literal `thebibliography`
block with all 47 entries already in IEEE format.

**Requirements:** `IEEEtran.cls` plus `amsmath`, `graphicx`, `booktabs`,
`array`, `makecell`, `cite`, `hyperref`, `textcomp`, `xcolor`, `url`. All of
these ship with TeX Live, MiKTeX and Overleaf — nothing needs installing.

**Use pdfLaTeX, not XeLaTeX/LuaLaTeX.** IEEEtran sets the paper in Times via
the `ptm` font shapes, which XeTeX's Unicode font encoding does not resolve; a
XeLaTeX build silently falls back to Computer Modern and loses bold and
typewriter text. Layout is identical either way, but pdfLaTeX is what IEEEtran
expects.

## Before submission

`main.tex` carries a placeholder author block (marked `% TODO`) — fill in the
full name, affiliation and contact address.

## Structure

Sections map one-to-one onto `academic.md`. IEEE numbers sections with Roman
numerals, so §3.1 of the Markdown is Section III-A here, §3.2.4 is III-B4, and
so on; all internal pointers use `\ref`, so they renumber themselves.

The 25 numbered equations appear in the same order as the Markdown's
`Eq. (1)`–`Eq. (25)`, so the printed numbers match the draft exactly. They are
referenced with `\eqref`, not hardcoded.

| # | Item | Placement |
| :-- | :-- | :-- |
| Table I | Folding / IK isomorphism | §I |
| Table II | Robots | §IV-A |
| Table III | Scenario hardness thresholds | §IV-B |
| Table IV | Baseline configurations | §IV-C, full width |
| Table V | Clean-solve rate vs. DOF | §V-D |
| Fig. 1 | KineticFold's compute schedule | §III-C1, full width |
| Fig. 2 | Success rate by arm | §V-A, full width |
| Fig. 3 | Per-solve latency | §V-B, full width |
| Fig. 4 | Real-mesh self-collision | §V-C, full width |
| Fig. 5 | Clean-solve rate vs. DOF | §V-D, single column |
| Fig. 6 | Solve once, score three ways | §V-F, full width |

Figures 1–4 are the four the Markdown calls out. Figures 5 and 6 are additions:
both are generated by the same committed scripts (`fig_dof_scaling.py`,
`fig_validation.py`) from the same committed data, and both illustrate sections
that otherwise carry no figure. Delete either float if you want to match the
Markdown exactly.

`figures/fig_deployment.pdf` is shipped but not placed — there is a
commented-out float for it in §V-E.

## Optional tables

`tables/` holds four generated tables from `paper/figures/make_tables.py`
(per-cell success on UR5 and Franka, the latency table, the UR5 collision
table). They are **not** included by default, because the Markdown reports those
numbers in prose and figures. Commented-out `\input` lines sit at the right
places in §V-A, §V-B and §V-C.

Enabling any of them shifts every later table number by one — Table V (DOF
scaling) becomes Table VI, and the prose reference to it updates automatically
via `\ref`, but the Markdown draft will no longer say "Table 5".

## Regenerating figures

The PDFs here are copies. To rebuild them from the benchmark data:

```bash
cd ../paper/figures
python build_all.py
```

Then re-copy the `fig_*.pdf` files into `figures/`.
